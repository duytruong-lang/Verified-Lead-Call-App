# Google Sheets pilot integration

The app database owns call outcomes, attempt history, verification, and handoff state. The configured source tab owns incoming lead fields. Sheet updates run asynchronously from a durable outbox; a Sheet failure never rolls back saved app work.

## Local first

Use the synthetic fixture at `fixtures/pilot/synthetic-call-sheet.csv` to configure and exercise mapping locally. It includes two separate leads sharing a phone number, finished history, and a formula column. It contains no real lead information. No live spreadsheet was accessed or changed for this implementation.

For a pilot copy, an admin selects the spreadsheet, tab, and header row, then explicitly runs Prepare on that selected copy. Prepare appends a technical `Verified Lead ID` header after the used range, assigns stable developer metadata to columns, and returns the metadata-backed columns to map. The worker attaches row developer metadata, assigns missing UUIDs through row-metadata-filtered writes, and verifies the whole source row before updating the UUID cell. The legacy preset is suggestion-only; confirm every suggested role before enabling sync. Store service-account JSON only in server environment secrets (`GOOGLE_SERVICE_ACCOUNT_JSON`); grant that service account access only to the pilot copy. Never put credentials in browser variables or commit them to Git.

## Mapping behavior

Phone and the app-managed UUID column are required. The app UUID is not a phone number, platform lead ID, or row number. Duplicate phones and missing platform IDs are normal. Rows with a duplicate app UUID block import and require reconciliation. Rows are tracked by row developer metadata and re-resolved by UUID after sorting. For rows without an app UUID, the worker creates row metadata, compares the full row, assigns the UUID through the row-metadata filter, and reads it back before import. Identical rows without UUIDs are ambiguous and stop for reconciliation. A row change during assignment is also blocked.

A mapping is valid only while its metadata IDs, headers, and schema fingerprint match. Missing/duplicate metadata, ambiguous duplicate headers, deleted or renamed mapped columns, or schema drift disables output. The worker writes only mapped output cells and leaves formula and unmapped columns untouched. Google Sheets has no cell-level compare-and-swap: a write with an uncertain timeout or server error is blocked and reconciled before any newer write is sent. The worker never treats a preflight read as protection from an already in-flight stale request. An expired worker invocation lease can recover automatically; an expired output-write lease is quarantined for readback and is never blindly reclaimed.

Legacy attempt outcomes and timestamps are imported as historical completed attempts without replaying them as new contact events. A legacy aggregate outcome/count that cannot be assigned to a particular attempt stays in source metadata and marks the row finished; it is not fabricated as a numbered attempt. Old recording URLs are retained as legacy source references and are not considered verified app handoffs. Verified tabs should switch from phone VLOOKUP to the stable app lead UUID before pilot output is enabled.

## Legacy workbook reference

The initial preset targets the `RAW-DATA-CALL-CENTER` shape. Header names, not letters, are used to suggest roles. Existing formulas and unused columns are preserved. The technical UUID column should be appended after the used area during deliberate admin setup. Do not overwrite blank-looking cells or create mappings from assumed column letters. Duplicate labels such as `Note` or `Record` must be resolved manually using metadata identity.

Migrate downstream lookup formulas in a copy of the workbook to join on the app UUID. A basic formula check is `=XLOOKUP($A2,'RAW-DATA-CALL-CENTER'!$<ID_COLUMN>:$<ID_COLUMN>,'RAW-DATA-CALL-CENTER'!$<VALUE_COLUMN>:$<VALUE_COLUMN>,"")`, where the selected ID/value columns come from the saved mapping. Verify that two synthetic rows with the same phone return their distinct values. Do not paste the angle-bracket placeholders literally.

## Worker and operations

Deploy the `sheets-admin` and `sheets-worker` Edge Functions after the matching database migration. Admin endpoints require a signed-in admin. The admin function accepts `prepare`, `discover`, `validate`, `save`, `status`, `reconcile`, and `repair-identity` actions. Prepare is a deliberate write to the selected copy. The status view lists identity conflicts as readable strings. After manually correcting duplicate UUIDs or row metadata in the selected tab, use Repair ID; the server clears the identity barrier only after verifying one matching UUID row and its metadata. Google OAuth and Sheets API access are server-only. Each worker run imports source fields idempotently, then processes durable output jobs. Repeated polls update source-owned fields; historical attempts/evaluation and current app state are initialized only for first import. Configure a Supabase Cron job to call `sheets-worker` about once per minute with the server `SUPABASE_SERVICE_ROLE_KEY`; do not expose that key in a client or source file. `supabase/cron/sheets-worker.sql` shows the once-per-minute job. It reads the worker URL and service-role key from Supabase Vault; do not put secret values in SQL or source control.

Outbox jobs are unique by lead and desired version, leased with a fencing token, and retried with bounded exponential delay. Repeated imports and duplicate requests are idempotent. A database-backed singleton worker lease serializes writes across overlapping Cron invocations. Import scans the two identity columns in one bounded values request to find the real last used phone row (not the tab’s preformatted grid size), prioritizes missing-ID rows near the end so newly appended leads are imported promptly, then refreshes 40 historical rows per run using a persisted cursor. At most five missing IDs are provisioned and three outbox writes are processed per invocation to keep Google API traffic bounded; existing identified rows use the faster import path. The status endpoint exposes cursor and batch budgets, and the initial historical import is intentionally spread across several runs. Duplicate stable IDs are detected across the full identity column before a row is imported. A job whose prior write may have completed after a timeout or server error is blocked for row reconciliation. Wait at least three minutes before reconciliation, then compare the Sheet row with the latest app snapshot; an older blocked job is marked superseded when the current row matches a newer version. Monitor blocked jobs and import progress before enabling a pilot. Never clear a blocked state until current Sheet cells have been read and compared to the current app snapshot.

## Verification limits

Automated tests use deterministic synthetic data and a fake Google HTTP transport. They validate mapping, identity allocation, formula preservation, locale-aware dates, retry/reconciliation decisions, stable handoff exports, and request construction. They do not prove that Google credentials, a live workbook, Supabase Cron, or Cloudflare deployment work. `realGoogle` remains untested until an explicitly authorized pilot copy is connected.
